## Corrections to tempting coverage claims

- **Read-only process death is adjacent to T12, not interrupted provisioning.** No DB/role creation or external call was in flight; there is no durable intent/outcome journal. The child checkpoint exports a preceding seed receipt, not a new receipt from its interrupted batch. Only the receipt checkpoint retains that seed live and unused until death.
- **Pair locking is a read-window control, not T13 cluster-wide lifecycle coordination.** Each batch holds an advisory transaction lock through its own inspections. Validation and handoff are separate batches, DB snapshots are separate, and an unrelated administrator/control plane is not fenced. Existing per-DB migration locks remain separate.
- **Password-change faults are not T17 rotation.** New authentication failure after fixture password change demonstrates fresh connection/refusal; it does not prove new-generation admission, existing-session drain/revocation, offboarding, unknown-outcome reconciliation or a rotation executor. Existing bootstrap does not replace an existing role password.
- **Catalog inclusion is not exhaustive adverse testing.** Reading grantor/grantability, object ownership/definitions or index state is weaker evidence than demonstrating rejection for each specified independent mutation. T07–T09 retain concrete coverage gaps despite the comparator and whole-inventory equality checks.
- **Actual local recovery is already demonstrated, but is a separate line.** S1 restore and SP04 encrypted/signed-journal recovery must not be erased from T18/T19 credit. Conversely, newer synthetic quarantine does not prove their integration, continuous hosted fencing, concurrent journal cutover, off-host custody, source loss or accepted promotion. SP04 temporarily admits only scoped privacy maintenance, then closes/revokes it; product roles stay closed.
- **Receipt digest and synthetic labels are not signing/attestation.** The pair accepts only the same in-memory live object; exported JSON has no authority. Hashes protect local comparison, not trust across processes or real image/config/credential-generation provenance. A fresh process revalidates instead of importing authority.
- **Current production entry points have not gained the prototype features.** Existing CLI `status` still calls a mutation-capable migration-lock helper; production SP01/SP02 preflight expects migrated schemas. Do not expose these prototypes as a hosted read-only lifecycle command or relax exact role/zero-membership/TLS/version rules.
