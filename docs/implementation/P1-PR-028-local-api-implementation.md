# Local public and owner API implementation

The owner explicitly authorized local API/frontend development and testing on November 2, 2026, while retaining S3 acceptance and deployment holds. This is an exception to the implementation dependency for P1-PR-028–032, not acceptance of P1-PR-027 or S4, or permission for a live release. Prior held-input reports remain historical snapshots of their recorded scope. Their immutable acceptance inputs are unchanged.

The next five implementation cards are public/owner APIs, staff/privacy APIs, callback/workflow APIs, aggregate local API validation and the accessible web shell. Their code can be reviewed and merged after local verification; actual source, specialist, provider, privacy, operating and hosted evidence remains required before acceptance or activation. The web shell may consume locally verified API contracts after the local S4 review; full S4 acceptance remains open.

The transport is a separate loopback HTTP host. It reuses application services and typed versioned contracts; no SQL, ranking or business rules enter a UI. Production web/worker hosts, database bootstrap and preflight policy remain unchanged. Public lookup returns permitted published data with coverage/source/freshness and pagination; absent data remains unavailable. No licensed source, supported tire recommendation or private provider delivery is invented.

Owner credentials are random, stored only as keyed hashes, and checked against current PostgreSQL owner sessions. Cookies are HttpOnly/SameSite Strict; local HTTP is loopback only. Mutations require exact Origin, session-bound CSRF, bounded JSON and command keys. Application commands provide durable idempotency/conflict handling. Shared capabilities use an Authorization bearer, never URLs. Errors carry server request IDs without internal messages. All responses are no-store/noindex. Admission uses the PostgreSQL limiter; missing policy fails closed. Local setup must explicitly provide a `local_http` version `1` policy; application startup never creates policy or identity records except an explicitly requested owner session.

All six S3 gates remain pending, HS01–HS08 proposed, operator/coverage/rate inputs unconfirmed, specialist/licensed work pending. No hosted provisioning, purchases, actual notifications, external provider dispatch, production authority selection or case/gate closure is authorized.
