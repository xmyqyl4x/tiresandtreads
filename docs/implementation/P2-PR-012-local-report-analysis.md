## Boundaries and processing choice

`createReportAnalysisServices` is an opt-in backend factory over transaction, owner authorization, report/source, consent, durable job, AI request/artifact/reuse/budget and provider ports. The dedicated database role is a trusted server capability, never an end-user credential or authentication substitute. No model, paid provider or credentials are configured. Implementation is tracked in [PR #100](https://github.com/xmyqyl4x/tiresandtreads/pull/100). The provider transport is injected; all execution evidence uses synthetic doubles. Official provider SDK/account controls and specialist quality evaluation remain pending.

An active owner session authorizes the current unexpired report version. Explicit processing permission records the notice, evidence hash and current subject revision. Declining preserves the ordinary deterministic report and creates no AI work. A withdrawal commits permission denial before attempting cleanup in a separate transaction, so a cleanup outage or contended budget cannot restore processing permission. Its reply reports `cleanupPending` when further cleanup is needed or unavailable. It immediately denies all processing under its guard, cancels up to 1,000 queued/in-flight records per bounded cleanup call and preserves started-work cost uncertainty. Remaining records are already unusable and the trusted cleanup port can drain subsequent batches without undoing denial. It prevents implicit reactivation. A new current explicit choice is required to enable processing again. Share-like tokens and foreign owners cannot obtain report requests or output.

The versioned immutable packet copies only allowlisted strategy, winter use, priorities, tire-size codes, deterministic option status/reasons/scores/budget codes and current permitted source references. Contact details, location, free text, session/grant tokens and raw owner identities are omitted. Source, bundle, engine, rule, schema and authoritative snapshot identities remain bound. Evidence reads preserve the existing 64 KiB input / 512 KiB output report limits, with a 640 KiB enclosing read bound; minimization still caps the provider packet separately at 32 KiB. A large-report review regression proves those limits with a supported immutable stored snapshot and a real thirty-plan engine output. Source display/API and AI processing/cache/derived/snapshot rights, current catalog head and reviewed rule are checked before enqueue, dispatch, publication and output reads. No license rights are inferred from availability.

## Model boundary and immutable publication

The server wrapper enforces strict JSON schema, no tools, no provider storage, bounded input/output and an actual abortable deadline. Refusal, incomplete/oversized/invalid output, unexpected errors and late results fall back without changing the core report. Model output selects supported claim IDs, exact source citations and fixed limitation/question codes. Critical numbers and reason codes are rendered from the deterministic DTO; arbitrary factual prose, HTML, ranking/cost changes and safety clearance are refused. This intentionally constrained first contract is assistance with choosing grounded explanations, not an accepted clinical or tire-safety assessment.

A fixed durable job binds request, report and expected attachment revision in the same transaction. Provider calls run outside SQL transactions. Per-attempt reservations precede dispatch. Measured charges are reconciled separately from publication so withdrawal, source change, stale job fences or attachment rollback cannot erase billing evidence. Unknown/excess charges retain reservations for reconciliation; exactly-once external billing is not claimed. Atomic immutable artifact, source provenance and attachment publication requires current permissions/source evidence plus job and reuse fences. Retrying accepted commands returns only their own attached artifact; another analysis request cannot substitute its output. Accepted artifacts last at most seven days and never beyond source expiry; retention is capped at thirty days. Read-time permission/source changes hide them immediately.
