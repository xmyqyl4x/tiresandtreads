## Service boundaries

The separate `packages/application/src/partners` namespace preserves the frozen P1 service inventory and gate checker. Three explicit application factories provide onboarding, offer moderation and coupon operations through typed ports. They reuse the existing opaque transaction, private-object and fenced job contracts. Pure commercial policy accepts an explicit clock; PostgreSQL adapters enforce current state, constraints and atomicity; integration adapters handle cryptography, structured files, CSV and inert previews. SQL adapters perform no provider/object I/O. No P2 HTTP route, browser credential, production executor or default runtime composition is added.

Every interactive command requires a `PartnerAuthority` attestation with verified email, provider subject, recent MFA (at most five minutes), session expiry and an optional staff identity. The service reparses the attestation and locks current SQL membership/capabilities inside its unit of work. A caller-supplied role, organization or staff UUID supplies no authority. Staff identities must match the attested provider subject and current role assignment. Tests inject fixed synthetic session handles; this port and its tests do **not** establish a real authentication provider, MFA challenge, session custody or production authentication acceptance.

## Durable coupon import

Queueing records an immutable organization/pool/asset/body identity and captured member revision/MFA deadline with a P1 durable job. The request does not parse the code file. A separate worker reads a bounded, versioned private object outside SQL, verifies its checksum/size and parses the fixed `code` column. Formula-like and malformed values produce bounded row/reason errors without raw values.

At most 500 rows per transaction enter private encrypted staging. Every batch checks the current organization/member revision, source asset, pool, authorization deadline and job generation/lease. A fixed lock function protects current authority without granting the worker organization or object mutation privileges. Duplicate detection spans batch/restart boundaries. Only a fully validated file publishes final codes, marks its pool ready and completes its job atomically. An invalid file publishes no final codes; row 100,001 rejects even after staging the first 100,000. Staging is removed on terminal publication/refusal.

Transient source/crypto/transaction failures remain distinct from malformed CSV. Committed checkpoints survive an interrupted later batch. Fresh MFA from the original requester can authorize a replacement job after the old lease is no longer live; a stale worker cannot publish through the new job pointer. There is no claim of exactly-once external delivery, independent durability or provider fencing. A bounded downloadable error CSV contains one-based data-record numbers (header excluded) and reasons only, with truncation reported. The 10% low-pool condition is returned as an operational flag; no recipient/operator notification is sent or accepted here. Matching, generated-code issuance, allocation, cap/frequency races and consented delivery are P2-PR-010.
