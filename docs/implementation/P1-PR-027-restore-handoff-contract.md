## Fixture and actor contract

The harness uses a fresh `tt-test-<16 hex>` project on a local Unix/npipe Docker endpoint only, two pinned PostgreSQL instances and four `tt_app_recovery`/`tt_cms_recovery` endpoints. All volumes/networks are owned and generated; the network is internal and no ports are published. No caller URL, SQL, archive, credential, phase, root/output path, effect callback, external Docker context or retained resource is accepted. Root/owner setup actors are trusted local preparation, not a daemon sandbox or independent security domain.

1. **Parent custodian:** verifies resolved service/volume/network/isolation shape and unused names, actual image IDs, container IDs/start times and mounts/aliases before and after the proof. It supplies a tooling image binding and sanitized configuration digest without secrets. Continuity at these boundaries is a local observation, not every-await fencing or attestation. It controls only exact owned actor termination and teardown.
2. **Setup and archive actors:** reuse unchanged recovery/custody/migration helpers where compatible. Add only fixed synthetic LR04 seeds needed by the existing populated `capture` reader before backup; update synthetic source fingerprints truthfully. Close source product CONNECT after seed preparation and before backup; target product CONNECT stays closed through restore/replay. Preserve fresh target secrets, complete history/ACL verification and the existing pre-restore custody refusals. No cluster role/secret archive import or target repair.
3. **Privacy maintenance:** reuse the real existing local privacy replay. Its temporary maintenance CONNECT grant is distinct from product traffic. Close the pool, revoke temporary CONNECT, verify all 19 scoped roles/zero memberships and owner-only database CONNECT across all four endpoints, and require no active scoped non-owner backend before sealing the new phase. Source and target state need not be identical after privacy replay; each has its own baseline.
4. **Checkpoint custodian:** in a separate fixed local step after replay, capture the existing durable synthetic privacy journal outside both databases and publish only bounded project/generation/digest/phase metadata to a separate read-only current-view mount. Bind its digest and observation time into the phase seal. Never derive current authority from the restored database or the archive itself. A current-view failure or later changed journal refuses; it is not permission to refresh a timestamp, replay extra work or select a production authority.
5. **Observer:** native verified CA/hostname TLS; exact session/current user, DB owner/name, PostgreSQL 18.6 and READ ONLY/repeatable-read facts. Use the unchanged bounded populated `capture` helper for fixed inventory/rows/sequences/role settings/ACL/history plus the new phase/checkpoint checks. It accepts no caller query or mutation callback. Repeated reads must leave each presented post-setup state unchanged.

## State, budgets and receipts

The only successful path is `artifact-admitted → restored-quarantined → privacy-replayed-quarantined → maintenance-closed → readonly-observed`. No state is a runtime release, production readiness or permission receipt. Missing, duplicate, out-of-order, unknown-effect or mismatched project/generation/manifest/image/config/head information refuses. The record is a trusted local fixture envelope, not independently authenticated authority.

Use the current reader's 200-table/sequence, 1,000-row/table, 1MB/table, 2MB aggregate rows and separate 2MB catalog, 100-history-row and 16KiB checkpoint limits; new combined public metadata is bounded at 64KiB. Native connection/query limits are 1500ms, statement/idle 1000ms, lock 250ms, transaction 5000ms, endpoint elapsed 6000ms and native-end observation 750ms. Setup/observer child processes are bounded at 180 seconds and exact owned teardown at 60 seconds. A timed-out await is not cancellation; absent end, backend or inspection evidence remains unavailable/unknown. No timeout enlargement, broad fallback or truncated evidence is allowed to make a case pass.

Receipts distinguish `success`, `refused`, `unavailable` and `unknown`. They expose case/phase/count/code/boolean facts only, never row data, URLs/passwords, keys, ciphertext or signed deletion entries. Setup receipts say `restoreExecuted: true` only after actual restore, and separately report actual privacy replay and maintenance closure. Refused-before-restore cases say false. The normal observer reports read-only observations, zero mutation/provider dispatches and false runtime/hosted/product/independent-authority flags. A separate fixed write-denial probe issues four permanent-table `UPDATE ... WHERE false` statements inside READ ONLY transactions, requires PostgreSQL `25006`, and reports those four rejected statements separately rather than calling them zero dispatched SQL. Original case/gate closures remain zero. Later physical cleanup never rewrites an earlier uncertain admission/observation receipt.

Post-observation comparison uses the snapshot **after** deliberate setup faults, preserving adverse state as presented. Source and target checks remain separate; no atomic cross-database snapshot or independent off-host/source-loss/RPO/RTO/PITR claim is made. If cleanup cannot be confirmed, retain private synthetic custody and block a fresh attempt rather than deleting unverified resources or claiming clean admission.

## Primary references and inference limits

[PostgreSQL 18 pg_restore](https://www.postgresql.org/docs/18/app-pgrestore.html) documents restore commands and archive-source trust. Therefore this fixture restores only its own generated archives; it is not an untrusted-archive sandbox. [pg_dump](https://www.postgresql.org/docs/18/app-pgdump.html) documents single-database archives; the two database restores are not a global transaction. [READ ONLY transaction rules](https://www.postgresql.org/docs/18/sql-set-transaction.html) restrict persistent data/schema changes but are not physical disk immutability or credential fencing. These are design limits; fixed queries and local actor custody supply the narrower observer boundary. No external provider price/eligibility/contract is researched or selected.
