## Fixed test boundary

Seven new files under tests only: [protocol/fixed record sequence](../../tests/fixtures/journal-process/contract.ts), [temporary file guard](../../tests/fixtures/journal-process/storage.ts), [private Node child](../../tests/fixtures/journal-process/child.ts), [parent/IPC controller](../../tests/fixtures/journal-process/parent.ts), [no-argument isolated runner](../../tests/fixtures/journal-process/run.mjs), [unit tests](../../tests/unit/journal-process.test.ts) and [use-case tests](../../tests/usecases/journal-process.test.ts). The accepted journal model/samples/runner/tests remain byte-for-byte unchanged. No production import, dependency/lockfile, migration, CI, version/TLS guard or previous proof changes.

The contract builds exactly **nine fixed synthetic records** from the unchanged model: operation, modeled acquisition, app intent, dispatch-observation label, app outcome, CMS intent/outcome, modeled quiescence and receipt marker. These are sample model observations, not executed provisioning or real target/SQL/provider effects. Plan fields bind the random fixture run/project, mode/point, simulated checkpoint and parent-exported receipt; caller paths, SQL, URLs, PIDs, programs, arbitrary records and extra fields refuse before fork. Child events bind actual owned PID/run ID and exact count/head/point, with fixed false authority flags and zero effect counters.

The parent creates a unique private directory directly under the resolved OS temporary directory, marks it with its random run ID and retains checkpoint/export **in parent memory only**. The child receives an explicit environment allowlist rather than the test container's database/provider credentials. Its file location is fixed by the owned environment/working directory, never a plan path. It accepts no standalone CLI/target arguments. One child per session is a cooperative fixture rule, not a cluster lock or production executor.

Normal file creation uses exclusive create; a new writer refuses an existing journal without overwriting it. Normal writes and reads are bounded at **65,536 bytes**; negative tests deliberately create 65,537 bytes to exercise refusal. Reads use bounded buffers, nonblocking/no-follow opens and regular-file/single-link/size/stable-stat checks. Real symlink/hardlink inputs refuse without changing their owned sentinel. Root/marker identity is checked before read and recursive fixture cleanup; a changed marker refuses cleanup until the test restores its own marker. This private fixture check is not authenticated ownership, independent custody or protection against an adversarial host/same-UID administrator.

Every complete record uses stop-and-wait IPC. Before advancing its checkpoint or allowing the next write, the parent independently reads the actual file and verifies its exact fixed prefix, model semantics and count/head. An ack message alone cannot advance it. An incomplete write or a complete record paused **before parent acknowledgement** leaves the old checkpoint intact. A fresh read child receives that retained checkpoint/export and must refuse mismatching/torn/tail bytes. It cannot discover a newer authoritative head from the file, truncate it, repair it, adopt it or dispatch a continuation. Imported receipt JSON refuses as appendable authority. Replay probing is in-memory refusal only; at acknowledged counts ≥3 the completed/unknown app step cannot be blindly retried.

## Actual interruption points

Each row executes a real SIGKILL of the owned Node child, awaits its actual exit and both stdout/stderr closures, then starts a different PID against the same owned file and retained parent checkpoint. Regular bytes stay unchanged through restart; missing/FIFO adverse states stay missing/FIFO. Dispatch is a **record label** throughout, with actual SQL/provider counters zero.

| Point | Parent-acknowledged count | File / modeled observation | Fresh child result |
| --- | --- | --- | --- |
| before-intent | 2 | Two complete lines; both planned steps not_dispatched. | Fresh read validates the prefix; no execution admission. |
| intent-ack | 3 | Intent acknowledged; app effect unknown. | Fresh read retains quarantine/unknown and refuses exported authority/replay. |
| dispatch-ack | 4 | Dispatch-observation label acknowledged; app effect unknown. | Fresh read remains unknown; actual SQL/provider dispatch counters zero. |
| partial-outcome | 4 | Four acknowledged lines plus part of outcome line five. | Fresh child refuses incomplete bytes; parent retains unknown at four. |
| outcome-written | 4 | Five complete lines; outcome was not acknowledged by parent. | Fresh child refuses tail/checkpoint mismatch; no automatic adoption/truncation. |
| outcome-ack | 5 | App success observed as synthetic input; CMS not dispatched. | Fresh read preserves app success; incomplete pair yields no product admission. |
| receipt-ack | 9 | Nine fixed lines, modeled quiescence and receipt marker. | Fresh read yields technical evidence only; all real authority/admission flags false. |

For partial/outcome-written cases, the parent-held exported state is explicitly asserted to retain the app's **unknown** effect. The fresh child refuses instead of issuing evidence for the unacknowledged tail. For the fully acknowledged prefix, matching file evidence still cannot enable runtime/product admission; `independentDurability`, `authenticated` and `targetFencing` remain false.
