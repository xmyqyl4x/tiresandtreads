## Implementation and run boundaries

Run `node tests/fixtures/tls-admission/run.mjs` from the repository root with a local Docker daemon. The host runner is portable plain JavaScript; all TypeScript, pg clients, certificate creation and tests execute in existing digest-pinned Linux images. It accepts no arguments, retained target, caller SQL, URI, role, callback, CA or timeouts. A separate [CI job](../../.github/workflows/fixture-tls-admission.yml) runs this command; the [existing full regression workflow](../../.github/workflows/ci.yml) stays byte-identical. No package/dependency, production bootstrap, CLI, preflight, old fixture, guard or hook changes.

Six fresh `tt-test-` projects cover normal TLS, expired leaf, future leaf, plaintext-only source, material-generation drift and credential drift. Each gets only two PostgreSQL 18.6 servers on a private internal network with zero published ports, separate data/key volumes, fresh synthetic public CA and distinct source/target leaf keys. A network-none certificate initializer writes UID-999/0600 keys; its root signing key exists only in that process memory. No existing recovery/custody runner initializes this proof. Fixed setup/teardown commands have explicit limits (120s compose operation, 90s health wait, 10s inspection/seal, 30s owned image-tag cleanup; image build capped at 600s). Temporary environment and binding files live under ignored `.local/`; exact generated project resources are removed, never broad-pruned.

The **privileged initializer is intentionally mutable**. It creates four recovery databases, invokes the existing bootstrap unchanged, creates the 17 app/two CMS scoped roles per domain, and revokes every nonowner runtime CONNECT in both domains. It captures role/membership/ACL/default-ACL/GUC/catalog baselines after both role sets exist. There are no migrations, domain seeds, archive restore, bad restore database, app/worker/provider startup or runtime admission. Admin setup uses legacy plaintext connections entirely inside this generated private network; it is not credited as verified observer TLS. All initializer clients close and its process exits before observation. Fixed later material/credential fault setup alters only the private synthetic file, then exits; it never repairs or re-adopts that generation.

The **trusted outer custodian** remains alive after setup. Before every connection/read and after awaited observed results, nonce-correlated bounded IPC checks fresh fixed Docker GETs, exact project/service/container IDs, running/healthy process incarnation, separate nonexternal owned volumes, aliases/internal network and private material generation. It rejects stale same-ID/same-volume process restart, unavailable supervision and changed credential/material bytes. Its Docker socket is mounted read-only, which **does not restrict Docker API authority**. This is trusted same-run test support, not a sandbox or independent physical-instance/authentication authority. The custodian and network-none binding helper alone receive read-only key/config mounts and `DAC_OVERRIDE` to inspect UID-999/0600 synthetic material. They expose only a combined comparison digest, never keys/credentials; digest equality is not authentication. The observer receives no Docker socket, root environment, server private keys or added capabilities. Its root filesystem and owner/trust/control mounts are read-only, with bounded writable tmpfs for tooling only.
