# P2-PR-024 - Local photo confirmation and manual assessment

The authorized local owner workspace now includes optional photo capture/upload, current purpose options, bounded owned history and explicit per-field correction. It reuses the established photo services, image codec, owner/session contracts and deterministic assessment form. Local implementation does not activate a model, accept source rights, validate actual image/model accuracy or close a release gate.

One additive owner-only read operation supplies the configured compatible active photo policy/notice and up to25 owned metadata records with a bound cursor. No private image URL, original bytes, grant or provider/model/prompt configuration is returned. Current intent, permission, subject, expiry and deletion barriers filter history; this fixes an observed integration failure where removed metadata remained in the older owner list. The query joins and filters the bounded result in SQL instead of issuing per-photo queries. History is explicitly refreshed and labeled with its check time. History starts from owned current intents and left-joins finalized metadata, so pending/processing uploads remain discoverable before finalization and never reveal their original grant or private object fields. This closes the reviewed interrupted-upload gap. Removal retains the existing202 queued cleanup contract: access is denied immediately; the existing privacy worker releases active quota during journaled cleanup. The integration proof runs that worker before asserting quota release and fresh admission; no immediate physical deletion or admission-policy change is claimed. All earlier71 operations remain semantically unchanged; the opt-in artifact now describes72.

Processing starts unchecked. JPEG, PNG and WebP are bounded to10MiB before reading, copied into page memory and SHA-256 bound to an explicit capture and upload intent. Finalization sends the exact prepared bytes and its original short-lived grant through a dedicated binary path. Only that path forwards the grant header and receives10MiB ingress; ordinary routes retain64KiB, and existing partner/CSV bounds remain. Scanning, decoding, size and current permission remain server authority. Progress identifies actual preparation/upload/check stages without estimating a byte percentage. Camera/file controls are optional; manual entry remains available. There is no background extraction or automatic replacement/retry after an uncertain command.

The photo panel shows each of nine field types separately, including raw visible text, unknown/uncertain quality, multiple conflicting values, partial DOT/TIN and explicit manual correction. Unknown candidates cannot be accepted as known. A confirmed field receives its exact server revision and origin; the first revision is1 and later edits use the observed revision plus one. Suggestions and confirmation do not alter assessment inputs. Ordinary form submission still validates both axles and persists through the same P1 report engine. While submission is pending, the surrounding photo and report controls are disabled so an external photo action cannot change the displayed answers during that submission. The connected form uses its existing owner session and original report key on an uncertain retry; it never creates an alternate identity.

Removing a photo clears private readings immediately while the existing journaled cleanup remains pending. Missing/expired selected-photo responses lead to manual recovery without disconnecting or erasing the assessment. A local expiry timer also clears displayed readings. Authentication/authorization failures retain the private workbench's disconnect behavior. Status/history reads remain possible during command reconciliation; new writes remain paused and original keys/receipts are preserved. A retake does not silently erase a previous upload; the owner can select it from history to request removal. This UI does not offer the separate save/extended-retention route.
