## Layers and composition

`domain/commercial-policy.ts` validates versioned policy, public route classes, reserved dimensions, first-party house targets, ads.txt's conservative line format, category/URL blocks, approved HTTPS affiliate origins and bounded aggregate reports. Calendar arithmetic uses explicit UTC values without a host clock. Application services depend on ports; PostgreSQL repositories own locking, CAS, audit and persistence. The integration factory checks exact `tt_staff_service_runtime`, `tt_commercial_runtime` and `tt_public_runtime` identities before composition, and reuses the common bounded-I/O adapter. No dependency or HTTP product route is added.

`createCommercialRuntime` requires accepted mail reconciliation/replay and privacy retry services. Those methods are delegated directly; no force-send, arbitrary job reset, consent override or deletion waiver exists. Its affiliate checker defaults to unavailable, has a five-second deadline and receives an abort signal. A later approved network adapter must restrict requests to reviewed public origins, pin/validate DNS destinations, reject private addresses and redirects, send no user context, and use bounded HEAD/status checks. This PR does not supply a general URL-fetching primitive or claim real link-health/provider acceptance from a fixture. Recovery has an outer ten-second deadline; existing services retain their own safety fences if a caller times out.

## Staff authority, queues and recovery

Every staff call receives a server-authenticated staff ID, never a browser-supplied claim of roles. The database authorization function locks the current active identity, unrevoked assignment and permission row through the query/mutation transaction. It allows only the enumerated service permissions. The migration seeds permission definitions, with **no identities, assignments or approvals**.

| Permission | Headless operations |
| --- | --- |
| `mail.recover` | Masked send/callback queues; known-ID reconciliation and verified-inbox replay |
| `privacy.review` | Masked rights/deadline queue; delegate the existing evidenced privacy retry |
| `data.review` | Masked import-state queue; existing import services retain publication ownership |
| `seo.publish` | Open SEO-finding queue; accepted content services retain CMS/publication ownership |
| `commercial.manage` / `affiliate.manage` | Preview/publish commercial policy, brand blocks, approved affiliate destinations and link checks |
| `revenue.import` / `revenue.read` | Stage/review/publish network aggregates / read correction-aware financial DTOs |

Queues have validated UUID cursors, 1–100 rows per call and indexed keyset pagination. Their DTO contains only resource ID, state and due time; it contains no address, contact/session/owner/report relationship, provider message ID, payload, proof, credentials or raw error. Separate role credentials cannot read the personal graph. Payload publication queues stay in the separate CMS service; no cross-database join or foreign key is introduced.

Recovery commands bind an immutable UUID receipt to staff actor, enumerated action and a digest of target/evidence. Only the winning concurrent insert invokes the existing service. Approval is durable before I/O, current authority is checked again before invocation, and a terminal audit is recorded afterward. Reusing a receipt with another actor/input conflicts. Failed, uncertain or process-interrupted receipts never invoke the action again automatically; an `executing` receipt left by a crash requires inspection. Successful command execution is not proof that the downstream manual-review case was fulfilled. A new explicitly reviewed command may reconcile again; it cannot create a new email. Receipts retain no raw consumer target ID. P1-PR-027 must bind monitoring, retained-receipt policy and crash/unknown runbooks to the scheduler; S4 binds staff identity/MFA, CSRF and transport authority.

## Commercial policy and affiliate safety

`preview` validates without writing. `publish` requires distinct active staff reviewers, a current policy, expected configuration version and a transaction-wide publication lock. It appends immutable `commercial_policy` history, updates the declared slot inventory and audits both actors. It cannot edit scoring, rank weights, prices, tire facts, source rights or consent. Published policy lasts at most 24 hours; an expired latest policy never falls back to an older revision.

Only live, reviewed public-register pages in education, glossary, tire-model and tire-size classes can receive slots. The home/form, decoder route, report/share, comparison, email/PDF, privacy, account and staff paths reject **all** placements, including house content. An allowlisted route without current published content also receives none. There are at most two reserved units per class, with explicit width/height, first-party house target and text label; Auto ads, refresh, scripts and HTML are absent. Private results remain disabled; any later result-shell exception requires separate isolation/network evidence.

External decisions require the host activation approval (default false), current published global advertising flag, current commercial policy, verified account bound to published configuration, consent, available CMP, no GPC, no internal traffic, and an unblocked/filled result. Known under-13 context receives no slots. Denied/no-choice, unavailable CMP, blockers, no-fill or unapproved networks use first-party house content only on permitted inventory. Category/URL policies and stored brand blocks are supported; **external serving stays off while any such block awaits actual provider synchronization**. This conservative gate cannot claim that a network has applied a blocklist. Labels are `Advertisements` for external inventory and `From Tires & Tread` for house content. Validated ads.txt text is returned only with current network readiness; account creation, actual seller IDs/site verification and network validation remain operator/provider gates. No placeholder seller is seeded.

Affiliate configuration requires a distinct reviewer, active retailer, approved application and ready terms asset, an exact reviewed HTTPS origin, no credentials/fragments/backslashes/private parameter names, and a restricted static attribution-parameter vocabulary. It uses expected link revision. Public resolution additionally requires a fresh valid check bound to **that destination and revision**, and still-current retailer/application status. Changed, suspended, unchecked, invalid or unavailable links resolve to nothing. Returned DTO includes disclosure, sponsored/noopener/noreferrer and no-referrer policy; UI must use these. There is no consumer-ID attribution join or dynamic report parameter. Consented click receipts/transport belong to the accepted analytics and forthcoming API/UI boundaries. Commissions and advertising never enter the tire engine; a service regression compares actual technical evaluation output before and after publication.

## Aggregate revenue and corrections

`importReport` accepts normalized aggregate snapshots (maximum 1,000 rows, at most 366 days between endpoints). Unknown fields, private dimensions, malformed calendars, noninteger/overflowing values and ambiguous estimated+finalized rows at the same day/dimension/currency grain are rejected. Only `all`, actual public-page IDs and active registered slot IDs are accepted. No raw user/ad events, IPs, URLs, report/AI/photo identifiers or private joins are permitted. Historical public page/slot mapping and provider-specific source formats still require the actual reporting adapter; unsupported/unmapped dimensions are not guessed.

Account locking, immutable source revision/checksum/generation identity, deterministic row ordering and replay comparison prevent conflicting or partial imports. An unknown currency fails the whole transaction. Staging, all metrics and optional observations commit together as validated data. A separate approval call requires a distinct active reviewer and the expected current account generation. A correction must advance the declared source generation; stale publication conflicts. Upstream generation ordering is a reviewed adapter responsibility, not inferred from an opaque revision string or fetch order.

The adapter must supply the actual source fetch time; it cannot precede the period end date or lie in the future. Import time never masquerades as source freshness. A same-revision/content replay preserves the original fetch time; the transport timestamp is excluded from the content checksum, and re-polling unchanged data does not silently refresh its financial evidence date.

Each approved import is a **complete period snapshot**, not a delta. The latest approved generation covering each day replaces every older dimension/currency there, including omitted dimensions and empty corrections. Approved metrics, observations and source identity are immutable. Estimated and finalized earnings are alternatives, never summed. Signed integer minor units preserve negative corrections; currencies are always separate and there is no inferred conversion.

`revenue` returns exact source revision/generation/fetch time, requested day/dimension/currency, raw count strings and earnings status. Missing account/report/measurement is distinct from a measured zero. Fill and viewability use basis points; RPM uses currency minor units per thousand impressions. Consent coverage uses aggregate eligible/total requests; mean latency uses aggregate milliseconds/sample count. Ratios use bigint arithmetic and truncate toward zero; missing or zero denominators produce null. An adapter may populate eligible requests only at a comparable single-unit request grain; otherwise it supplies null. Missing consent/latency/viewability is explicitly unavailable, never fabricated from private analytics. There is no fabricated p95, net contribution or FX/cost total. Actual cost accounting, invalid-traffic baselines, provider synchronization/earnings imports and field measurements remain release/operations evidence.
