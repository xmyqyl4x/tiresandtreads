## Reviewed boundary and actor contract

Run `node tests/fixtures/io-inspection/run.mjs` from the repository root with local Docker. No arguments, retained target, URI, caller SQL, PID, key, callback, timeout override or generic proxy control is accepted. The parent checks the local Docker context and refuses name/label collisions before setup. Five fresh generated projects use the pinned two-instance foundation setup. Each has separate owned data/TLS volumes, public trust, four private owner endpoints and nonowner runtime CONNECT quarantine. The existing privileged initializer exits before observation.

The unchanged resource supervisor retains the Docker socket and private server-key custody. The unchanged SQL inspector retains the separate synthetic administrator mount and uses fixed read-only identity/backend/advisory-lock queries. The observer has read-only owner/trust/control mounts plus an owned private routing volume; no Docker socket, administrator password, server key, writable data mount, added capability or provider credential. The private binding is trusted local harness input, not independently authenticated provenance.

A fixed network-none metadata preparer reads only the parent's bounded binding and writes only an empty generated routing volume. It validates the exact metadata fields/project/generation, writes a UID-0 `0400` file and checks its digest. That actor alone receives `DAC_OVERRIDE` for the host-owned `0600` input; it has no database credentials, keys, network or SQL/provider path. The capability-free observer mounts the routing volume read-only and independently checks the file type, UID, mode and bound before reading. Linux CI exposed why directly mounting a different host UID's private file was unsuitable: Windows Docker Desktop did not reproduce that Linux DAC boundary. Host permissions are not widened and no capability is added to the observer. Five metadata-preparation receipts are harness observations, not additional Vitest cases or independent authentication.

The new observer starts two **loopback-only opaque TCP relays** inside its own container. Fixed hosts entries send the two canonical PostgreSQL names to `127.0.0.1`/`127.0.0.2:5432`. Upstreams are the two addresses in the original validated private binding, always port 5432. The native driver still uses canonical names, verified CA/hostname, TLS 1.2 minimum and PostgreSQL SSL negotiation. The relays do not terminate TLS, parse SQL, substitute database replies or receive server keys. They are internal fault support, not a reusable routing API or new admission authority. Buffer/backpressure limits, at most eight accepted sockets per relay and a separate twelve-second connection watchdog bound the synthetic actor. Withheld encrypted bytes are counted and discarded, never printed or replayed.

Only the trusted parent stops an inspector or resource supervisor, after a fixed observer cue and a fresh exact container ID/image/project/service/running-state check. It confirms that owned service stopped, then writes the fixed private continuation marker in the owned observer. No database container is stopped and no backend-termination SQL is added. The parent's watchdog is not permission to extend the observer's four-second admission window.

## State, timing and cleanup contract

Admission uses one monotonic start and a **4000ms** window. Remaining work is at most **1500ms** per operation. The new observation helper checks elapsed time both on timer expiry and after awaited delivery, so an event-loop-delayed timer cannot admit an already late result. A pending Promise remains pending work; an observation timeout never establishes cancellation. Native driver query/connect limits remain bounded; the read-ack hold uses a tighter 350ms query cap. Server statement/idle limits stay 1000ms, lock 250ms and transaction 5000ms. Resource/SQL IPC uses a separate absolute deadline of at most 750ms, with nonce and bounded-response checks. Periodic data cannot reset that deadline.

Before each fixed connect/query dispatch, calculate remaining time. Re-admit environment/private context and the fresh resource map at declared boundaries, including after connect, registration, facts and final read delivery. A lost map, changed context or expired budget discards the provisional result; no replacement binding, fallback transport, successful cached sample or replay is substituted. This is declared-boundary coverage, not a claim of atomic check/use exclusion, preemption or validation at every possible await.

Admission success is recorded only when the native read and all required post-read validations actually return successfully, independent of the scenario name. Tests separately require positive scenarios to reach that outcome and negative scenarios to reject it; they also require an observed refusal reason. A temporary final-guard-removal mutation must fail the late-source/late-target and context-drift-source/context-drift-target controls. The mutation is never published; exact source restoration and owned cleanup are checked before the final unmutated proof. Its deliberately failed controls are separate regression evidence, not additional passing executions or original case closure.

Cleanup is a separately timed observation: at most 750ms to observe native driver end, then up to 2000ms of fresh exact registered-identity/backend/lock samples. The two owned relays are disposed together under their own 750ms bound, explicitly awaiting both listening-server and socket close events. A later native end is observed separately. Cleanup can outlast admission; no four-second total-runtime claim is made. A registered backend requires fresh inspector absence; a driver end or relay close alone cannot establish absence. For partial-connect controls, the actual relay reports zero upstream opens and no registered SQL backend, so no backend-absence observation is claimed.

If driver end or required inspection is unavailable, freeze `cleanupUnknown=true` and block a fresh attempt in that observer process. Later relay disposal, driver end, parent audit or project removal does not upgrade that receipt. `readCompleted`, `readAccepted`, driver end, inspection availability, backend absence and lock absence remain separate fields. A known refused SQL outcome such as native `57014` is distinct from an acknowledgement lost in encrypted transport. No cancellation, administrator exclusion, authentication, independent durability or target-fencing claim follows.

## Implemented fixed matrix

| Controls | Actual observation | Required disposition and limit |
| --- | --- | --- |
| Positive source / target | Native TLS, exact user/session/database/version/owner/read-only facts, registered identity and successful fixed read | Admit the local result only after revalidation and known cleanup |
| Partial connect source / target | Relay accepts native eight-byte SSLRequest but opens no upstream and sends no response | Bounded refusal, zero owner query calls, observe owned end; do not claim inspected backend absence |
| Dropped connect source / target | Relay observes the SSLRequest and closes its owned TCP stream before upstream open | Native connection failure, zero queries, known owned closure |
| Withheld read reply source / target | Authenticated connection and facts first; relay discards real encrypted server bytes from the fixed read | No delivered result; request may have completed remotely; refuse without replay; fresh cleanup inspection remains separate |
| Dropped read reply source / target | Same fixed read, but close the actual streams on the encrypted reply | Native read failure; no application result; exact cleanup observations |
| Server statement timeout source / target | Fixed `pg_sleep(2)` under unchanged one-second statement timeout | Native `57014`; do not describe every client deadline as server cancellation |
| Late delivery source / target | Native read actually completes and rolls back; harness withholds application acceptance until the original window expires | Discard completed result after 4000ms; no reset or timeout increase; this is delayed application delivery, not wire acknowledgement loss |
| Context drift source / target | Harness changes the fixed provider-mode marker after native read completion | Refuse at the post-read guard, discard result; trusted test teardown restores its marker only after the attempt is terminal |
| Delayed native end | Only this fixed control enables the pinned native driver's pipeline option. After the inspector observes the real source advisory lock, withhold encrypted bytes from an actually pending read and call native `pg.Client.end()` while it waits for drain | End remains unobserved at 750ms. | Inspector loss | Parent stops the exact owned inspector after native read completion | Refuse, driver end distinct from unavailable backend/lock observation; freeze unknown, block fresh attempt |
| Resource-supervisor loss | Parent stops the exact owned resource supervisor after native read completion | Post-read admission fails and discards result; still obtain cleanup from the surviving SQL inspector |
| Supervisor loss before connect | Parent stops that owned supervisor before owner connect | Refuse with zero owner connects/queries, no registered-backend absence claim |
| Stalled / dribbling Unix peers | Two explicitly synthetic native socket peers, no SQL/custodian authority | Absolute 80ms observation bound despite inactivity or periodic bytes; dispose exact local sockets |
| Six budget controls | Pure arithmetic, controlled clocks/Promises, withheld/late success/rejection and timer disposal | Model evidence only; includes the behavioral red for late delivery accepted before a delayed timer callback |
