## Proposed fixed plan and identity boundary

This section is an unimplemented test-support contract. The proposed exact five-field envelope is `version`, `scope`, `project`, `fixtureGeneration`, `domains`: version 1; scope `disposable-readonly-multitarget-plan`; exact `tt-test-` plus 16 lowercase hex project; 32 lowercase hex generation; maximum **4,096 UTF-8 bytes**. Reject unknown/duplicate keys, malformed/non-finite values, wrong environment/provider mode, missing/extra domains and oversized input before handles exist. Raw JSON decoding/canonicalization must be defined and tested in a later model proof; ordinary JSON parsing that discards duplicate keys is insufficient for a raw-text interface.

`domains` is exactly two records, each with only `slot` and `purpose`. Fixed binding is slot **0/source → postgres** and **1/target → recovery-postgres**, with exactly app then CMS endpoints at the existing recovery DB names/owners. Input enumeration may vary; source/target assignments cannot. `_bad`, retained dev/stage/native/remote targets, arbitrary names/URIs/CA/credentials/OIDs/keys/timeouts/SQL/callbacks/programs/receipts/archives/journals refuse. Values are detached and immutable; re-admit at connection and command boundaries and after awaited acknowledgements/results. No plan is bearer permission to execute a lifecycle step.

An independently supplied **within-harness immutable map** must bind the exact generated run, service slot, actual owned container ID/data-volume ID and endpoint/credential/TLS generation. It must be constructed by the later owned fixture supervisor, never trusted from this caller envelope. Exactly two distinct physical fixture bindings are required; aliasing both slots to one service, mixed projects/generations, replacement/restart or inability to resolve binding refuses. This is a proposed same-run local assertion, **not independently authenticated cluster identity**. Names/host labels/OIDs, timestamps, semantic hashes or a PostgreSQL lineage identifier alone cannot attest an actual cluster instance; cloning/routing and external-admin continuity remain outside this proof. No new privileged identity query or role membership is authorized.

The PostgreSQL [client certificate verification reference](https://www.postgresql.org/docs/18/libpq-ssl.html#LIBPQ-SSL-PROTECTION) distinguishes chain and hostname checks. This is a general requirement, not a claim that Node's driver consumes libpq `sslmode`. Later fixed Node settings must explicitly require trusted CA, matching hostname and observed TLS/DB/role/read-only/version facts with no downgrade. [Server TLS support](https://www.postgresql.org/docs/18/ssl-tcp.html) alone permits plaintext unless the access policy requires TLS. No TLS/client/server configuration is changed here.

## Proposed acquisition order and bounded lifetime

PostgreSQL [documents consistent lock ordering and cooperative/session lifetimes](https://www.postgresql.org/docs/18/explicit-locking.html#ADVISORY-LOCKS). It also documents [database-local advisory locks](https://www.postgresql.org/docs/18/view-pg-locks.html) and [server-local, non-WAL-replicated scope](https://www.postgresql.org/docs/18/hot-standby.html#HOT-STANDBY-CAVEATS). **Design inference:** a source lock does not allocate the target, and equal keys in different DBs or servers do not supply a shared lifecycle allocation. The following is a proposal for participating local fixture sessions only.

1. Admit the complete immutable two-domain plan and separate harness binding before any allocation. Reject an existing held inner handle, reused participant, incomplete cleanup or request to add a domain after allocation starts. Never acquire in caller/source/target string order or discover the second domain after doing work on the first.
2. Acquire **common[0] then common[1]**, each on its own domain's existing `tt_app_recovery` / `tt_app_migrator` connection. Reuse PR54's numeric **fixture-only** key `7724054,1` as a proposed session-level exclusive try-lock. Try once, nonblocking, without polling, stacking/reentrant reacquisition, shared-lock upgrades, fallback or automatic retry. Both allocations must remain live before any inner/work command. It is not an atomic two-server allocation.
3. Only after both commons are held, acquire fixed inner controls in **0/app → 0/cms → 1/app → 1/cms** order, each on its exact existing owner/DB connection. Proposed fixed session try-lock is the existing `7724004,1` in each DB; CMS uses the same numeric key in CMS, not an invented second namespace. Never call `withMigrationLock`, CMS migrator or CLI/status: those paths can write metadata. [Source](../../tests/fixtures/readonly-coordination/proof.ts#L7) [Source](../../scripts/database/migrate.ts#L38) [Source](../../scripts/database/cms.ts#L16)
4. Run only separately reviewed fixed read-only metadata/catalog/synthetic-data observations on admitted channels; recheck both common sessions and binding before/after every awaited operation. No caller SQL/secret/callback is accepted. Observe separate snapshots/windows truthfully; they are not an atomic cross-DB/cluster snapshot. Hashes/receipts summarize observations, not continuing authority.
5. Finish all bounded reads and post-read checks while allocations are still owned. Close inner/work handles in reverse acquired order, then common 1 → 0; await exact owned session ends and inspect lock absence when available. A session lock survives transaction rollback until session end; rollback alone is not release. Never unlock another participant or terminate/revoke an arbitrary backend. Record cleanup unavailable/unknown rather than a clean result when observation fails.

Use the existing strict read-only limits as **proposed later proof constants**: connect/client query ≤1,500ms, statement/idle transaction ≤1,000ms, lock ≤250ms, transaction ≤5,000ms. Add a **4,000ms monotonic whole-attempt budget** starting before connection/admission work; no per-domain/step reset. These numbers are unmeasured here. Four endpoints/two commons may consume the budget; fail/refuse rather than increase existing guards or hold a transaction open for human review. Earlier common sessions also retain the 1,000ms idle-transaction cap while later channels connect; no heartbeat loop or guard relaxation is introduced to keep them alive. Each call must be capped by remaining time, and any result arriving after expiry must be discarded. Timeout is an admission boundary, not proof that target work or cleanup finished by that deadline. [Source](../../tests/fixtures/lifecycle-validation/reader.ts#L118)

The local endpoint is deliberately not a production choice: using a DB that may be restored/rebuilt cannot establish the original surviving-authority requirement. No production maintenance DB, lock namespace, external coordinator, provider support, extra LOGIN or SET/ADMIN exception is selected. The exact 17 app + 2 CMS restrictive roles and zero scoped memberships remain unchanged. An actual lifecycle path still needs separately reviewed authority/current journal/index and operating boundaries; obeying this proposed order does not make unrelated migrators/admin/control planes participate.

## Refusal, lost sessions and source preservation

| Boundary | Required proposed behavior | Evidence limit |
| --- | --- | --- |
| Common 0 busy/unavailable | Stop; no common 1/inner/work; close any already opened owned channels | Refusal is local, no production availability result |
| Common 1 busy/unavailable after 0 acquired | Mark whole attempt refused; close all owned work/inner handles and common 0; no partial evidence result or retry | Owned prefix cleanup is not rollback of arbitrary effects |
| Inner endpoint busy/identity mismatch or environment/generation drift | Invalidate complete attempt; stop new queries, close owned prefix in reverse; preserve target quarantine | Fresh input/receipt cannot resume an old held state |
| Either coordinator lost, expired or observation unavailable | Invalidate all candidate observations; stop new work on both domains; close owned handles, retain unknown cleanup when needed | A new holder or PID disappearance cannot prove old independent work quiescent |
| Independent fixed read already in flight | Allow its bounded completion/driver error to be observed; discard result after allocation loss/expiry | PR54 already showed independent work can finish; result refusal is not cancellation/fencing. [Source](../../tests/fixtures/readonly-coordination/proof.ts#L155) |
| Incomplete cleanup or unobservable remaining work | No clean receipt/re-entry recommendation; keep refusal/quarantine and explicit unknown facts | Do not escalate to root/kill a foreign session or claim universal cleanup |

For a later SQL proof, declare a baseline **after separately admitted owned synthetic setup and before allocation**. Compare before/after source **and** target schema/ACL/grantor/GUC/history/role/membership plus bounded synthetic data fingerprints; no source/target data/DDL/role/password/grant/repair/replay/restore mutation belongs to the probe. Coordination changes transient session/lock state and can affect statistics; do not claim bitwise immutable database files/counters. Source preservation is relative to this new baseline, not to the old pre-backup inventory after the historical seal intentionally changed source. The full recovery/custody success path must never run as the new observer.

All target product/runtime CONNECT remains closed throughout every success/refusal/loss/cleanup state; no maintenance worker grant, application/worker/provider service start or automatic runtime opening. An owner credential is not intrinsically a read-only account: a later strict interface/transaction constrains its fixed queries, without changing role policy. Fixture setup/teardown would have actual local effects and need their own disclosure; the present review starts no fixture, SQL session or provider.
