## Consent, fallbacks and live bindings

The controller denies `ad_storage`, `analytics_storage`, `ad_user_data` and `ad_personalization` before reading consent or invoking an adapter. Trusted composition must separately supply activation, network readiness and a verified CMP/creative adapter. A known under-13 context hides all inventory. Missing ads consent, unverified CMP, GPC, internal/bot context, invisibility, density refusal, no-fill, blocked creative, error, cancellation or a five-second consent/creative deadline leaves denied house content. Purpose grants are independent; ads consent never implicitly grants analytics or personalization. Withdrawal and page lifecycle invalidation cancel stale work and dispose an admitted adapter. Cross-tab messages can only revoke; they cannot grant permission or supply configuration. Local privacy save attempts notify this invalidation channel before network work.

**The shipped local browser entry deliberately supplies no creative adapter and hard-codes activation/network readiness false.** It loads no Google SDK, ad iframe or external tag. The controller’s adapter/CMP behaviors are covered by synthetic port tests; these are not actual vendor integration, CMP certification, regional legal acceptance or real ad-delivery proof. A real certified CMP binding, provider SDK/creative mapping, approved publisher/account/terms, current regional/privacy policy review, production kill-switch/withdrawal behavior and permitted real-provider evidence remain required before any later live activation. No client storage, URL parameter, message or fixture flag can authorize that activation in this change.

`/ads.txt` is read afresh through the existing service’s current account/policy/global-switch checks. An unconnected, suspended or unavailable configuration returns a comment, never a fabricated publisher ID. A synthetic approved record is exercised only inside the disposable database test. Serving an authorized ads.txt body alone never admits an advertising SDK.

## Affiliate behavior

The fixed reviewed key `approved_retailer` is optional. The existing service must confirm an active retailer, approved current terms and recent successful health evidence for the exact link revision. The UI displays the commission disclosure next to the link, marks it sponsored/nofollow, sets no-referrer and links to a script-free disclosure page. This is local copy for review; actual policy/legal acceptance remains pending.

The first-party `/go/approved_retailer` route rechecks those requirements at click time, validates the destination using the existing domain policy and returns a no-store/no-referrer redirect. It rejects private query parameters, arbitrary keys, unsafe destinations and upstream failures. Owner cookies and report/contact fields are never forwarded. It does not create a click-attribution record. Public reads use fixed loopback paths, omit credentials, reject redirects, cap the response at 32 KiB and bound headers plus body reading by five seconds, including an upstream that ignores cancellation.
