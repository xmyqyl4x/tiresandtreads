The published [minimatch release](https://github.com/isaacs/minimatch/releases/tag/v11.0.1) and [glob release](https://github.com/isaacs/node-glob/releases/tag/v14.0.2) cross their parents' previous major-version ranges. They are intentional, measured compatibility exceptions, not an untested broad update. Their published Node engine ranges include the existing Node 24 runtime. No direct dependency is added or upgraded. The generated lockfile records the changed transitive closure, including minimatch's nonrecursive matcher and glob's newer path-scurry; obsolete glob CLI dependencies are removed. Existing strict-peer, release-age, allowed-build and high-severity audit settings remain unchanged.

The small deepmerge patch rejects the literal `__proto__` key before either the source guard or target-copy loop can read or assign it. It applies to `index.js`, `dist/cjs.js` and `dist/umd.js`, preserving the package version, dependencies and MIT license. The CommonJS and UMD bundles are exercised; the shipped source is patched consistently but is not represented as a separately executed public entry point. Legitimate own `constructor` fields, nested cloning, arrays, symbols and custom merge callbacks retain their tested behavior. The observed getter control verifies that the forbidden key is skipped before getter invocation. This is a local mitigation of reproduced cases, not an upstream release, exhaustive security proof or assurance about arbitrary caller-provided merge callbacks.

[pnpm's version-specific patch mechanism](https://pnpm.io/cli/patch) records the patch and its SHA-256 in the lockfile. Default failure on unused or inapplicable patches remains enabled. Docker's dependencies stage now copies `patches/` before its existing frozen install, so development, verification and application image builds consume the same patch. A missing/mismatched patch must fail installation. No audit ignore or advisory exclusion is added: the published low-severity deepmerge warning remains visible because the registry describes the unmodified upstream version. The evidence distinguishes that warning from the installed local mitigation.

## Test-driven implementation and bounded execution

Eleven regression controls execute the actual installed dependency instances in owned Node child processes, with 128MiB heaps, five-second parent deadlines and 64KiB output bounds. They resolve minimatch through ESLint, TypeScript's parser/estree and the real Inngest/GCP/rimraf/glob chain. They resolve deepmerge from Payload rather than adding a convenient unrelated test dependency.

The final tests were run against an immutable cached vulnerable Linux image with the same test/probe files mounted read-only. Seven cases failed as intended: versions, minimatch expansion budget, post-abort glob traversal, three returned-prototype shapes and a forbidden getter. Four normal behavior controls passed. These expected negative-control failures are distinct from passing regression totals. The patched Windows installation passes all eleven controls; a fresh pinned Linux build independently installs the frozen graph and patch and executes the same controls.

The minimatch control checks a fixed pattern against an explicit 32-entry expansion budget. The fixed implementation may stop expansion without throwing; the test checks the resulting bound rather than assuming an exception. The glob control wraps actual filesystem `readdir` calls, aborts after the first real read and checks that no more traversal is dispatched in the bounded synthetic tree. Neither directory entries nor walk results are mocked. These are representative observed bounds, not a general cancellation/fencing claim.

Temporary directories are generated under the resolved OS temporary root. The parent checks the exact absolute directory, parent and symlink state before recursive removal on Windows or Linux. Child-process tests make no external calls. The dedicated runner accepts no arguments, requires local Docker, uses an owned generated image and three fixed actors, and verifies cleanup. Contract tests have no network, mounts, administrator credentials or provider path; their scratch/cache filesystems are bounded tmpfs mounts. Audit actors alone access the public registry. Their native pnpm status and all-severity warning records are retained. Parent timeouts have owned-identity-checked cleanup; timeout alone is not represented as cancellation.

Run `node tests/fixtures/dependency-compatibility/run.mjs` for the fresh Linux install/audit/contract proof. The independent dependency-compatibility CI job runs that command. The ordinary full build/regression includes the eleven unit controls too; those counts overlap and must not be added as unique coverage. All seven pre-existing CI jobs also run on the new dependency graph.
