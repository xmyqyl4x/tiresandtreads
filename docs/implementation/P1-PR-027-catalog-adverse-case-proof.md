## Fixed fixture setup and read-only boundary

Three new files only: [SQL assertions](../../tests/database/lifecycle-catalog.test.ts), [fixed probe fixture](../../tests/fixtures/lifecycle-catalog/database.ts), [no-argument disposable runner](../../tests/fixtures/lifecycle-catalog/run.mjs). Existing test discovery runs the new DB file automatically; scripts, dependencies/lockfile, migrations, CI, runtime/version/TLS guards and all 49 previous source pins are unchanged.

The helper first reuses existing disposable-target admission and the accepted phase fixture. In each exact app/CMS DB it creates a fixed synthetic schema, a public probe table with two duplicate values, a standalone sequence, enum and two routines, a scoped RLS policy and known probe ACLs. Two additional **unscoped NOLOGIN grantors** allow a real grantor-only comparison; a third **unscoped NOLOGIN owner sink** keeps ownership changes separate from that grant graph. These are private test actors, not additions to the 19 project-role policy or a provider permission exception. Root is the existing privileged local setup control, never a product credential.

The active profile's catalog digest is captured **after this fixed setup and before any fault**, then frozen. The original source, DB ACL and history baselines remain unchanged. Foundation keeps application migration metadata absent; the probe objects are controlled test sentinels, not a production foundation manifest. No caller SQL, repair mode, URI, retained target or user-supplied baseline is admitted by the runner. Each fault begins with clean semantic snapshots and compatible both-DB reads. Independent SQL verifies the actual defect, then the unchanged TLS/read-only reader must refuse and leave the defect/snapshots untouched. Explicit test cleanup reverses only that fault; snapshots and fresh both-DB compatibility must return to the original baseline. The baseline is never recaptured to learn a defect.
