## Proposed TLS material and client contract

Use a fresh synthetic per-run CA with **two distinct leaf certificates/private keys**. Each leaf has only its fixed positive DNS SAN, server-auth usage and explicit validity; negative material includes an unrelated valid root, expired/not-yet-valid certificates and mismatch aliases. Preserve the old certificate generator/default profile; any new generator/output set is separate test support. Root signing material stays in the owned initializer's memory/temporary custody and is not published/retained; source/target leaf keys go only to separate server-owned mounts, with Linux ownership and 0600 restrictions. Observer gets public trust material only, bounded to 65,536 bytes and exact current generation; byte/key/validity/custody mismatches refuse. No actual certificate/key is generated in this review. [Source](../../tests/fixtures/database-preflight/certificates.py#L12)

A future **new test-only client factory** constructs explicit host/port/database/user/password and SSL object fields from its private fixed map. Require the owned public CA, `rejectUnauthorized: true`, default hostname verification and minimum TLSv1.2. Reject injected connection strings, SSL query parameters, custom identity callbacks or ambient PG/TLS configuration; sanitize the observer environment and keep traditional SSLRequest negotiation. No fallback to no-verification, plaintext, IP/localhost, alternate host, administrator or additional membership. The [driver SSL documentation](https://node-postgres.com/features/ssl) explains why mixing URI SSL parameters can replace an SSL object. [Node 24 TLS documentation](https://nodejs.org/docs/latest-v24.x/api/tls.html#tlsconnectoptions-callback) describes CA/hostname checks; its page currently identifies v24.22.2, while the project remains pinned to **Node 24.22.1**. Text inspection of installed/pinned **pg 8.23.1** confirms the host/hostname and negotiation paths; this is not an executed driver compatibility test or version upgrade. [Source](../../tests/fixtures/lifecycle-validation/reader.ts#L75)

The dedicated future profile would enable TLS on both services using the separate leaf/key mounts/aliases. **Server-wide plaintext rejection and mutual TLS are not selected or claimed.** Existing legacy fixtures permit ordinary connections; [PostgreSQL TLS enablement](https://www.postgresql.org/docs/18/ssl-tcp.html) alone does not require encryption for every client. [HBA rules](https://www.postgresql.org/docs/18/auth-pg-hba-conf.html) have separate matching semantics. No HBA/production policy change is included or silently authorized. The narrow observer must nevertheless require verified TLS for every admitted connection; a plaintext-only endpoint must refuse rather than downgrade. [Source](../../infra/local/02-test-tls.sql#L3)

For **each of the four endpoints**, require successful verified client TLS connection and a fixed bounded read of exact `current_user`/`session_user`, DB name/owner, `server_version_num` **180006** from unchanged PostgreSQL 18.6 pin, read-only `on`, repeatable-read isolation and current-session TLS use. No `SET ROLE` fallback or privileged identity query is authorized. Existing reader shows a fixed fact query and exact-version comparison but cannot be widened/reused as recovery admission. [Source](../../tests/fixtures/lifecycle-validation/reader.ts#L257) [Source](../../tests/fixtures/lifecycle-validation/reader.ts#L344) The [PostgreSQL SSL view](https://www.postgresql.org/docs/18/monitoring-stats.html#MONITORING-PG-STAT-SSL-VIEW) supplies session TLS-use facts; **its SSL boolean alone cannot prove client CA/hostname verification**. Null/ambiguous/mismatched facts refuse, including unchanged names on a wrong domain.

Preserve proposed inherited caps: connection/client query 1,500ms, statement/idle 1,000ms, lock 250ms, transaction 5,000ms; one monotonic **4,000ms whole admission-attempt budget**, starting before binding/admission work, no per-endpoint reset. This does not include privileged setup or guarantee cleanup has completed by the deadline. Each asynchronous operation must be bounded by remaining time; late completion is observed/discarded with unknown disposition where needed. Four sequential connections may exhaust the budget: refuse/reduce the future observation set or split a separately reviewed attempt rather than raise limits. No timings are measured here. [Driver client options](https://node-postgres.com/apis/client) and the existing strict wrapper are reference points, not a tested new implementation. [Source](../../tests/fixtures/lifecycle-validation/reader.ts#L118)

Return only bounded fixed IDs/counts/status, fixed error categories, observed session closure or explicit unknown cleanup, and false lifecycle/journal/production authority flags. Never log raw URI/password/CA/private key, arbitrary error text or table rows. TLS/login facts, when later observed, must be reported separately from the still-false independently authenticated lifecycle/journal authority flag. No connection/cache receipt authorizes reuse after restart or currentness loss.
