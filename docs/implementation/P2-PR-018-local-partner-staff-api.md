## Common HTTP contract

Versioned contracts live in packages/contracts/src/phase2-partners.ts; clients and combined generated OpenAPI validation are the next API-gate card. Each adapter parses a closed schema, obtains the verified actor, invokes its shared service and projects named DTO fields. GET query keys, UUIDs, revisions, quantities, page sizes and clocks are bounded. Mutations require matching Origin, CSRF and an idempotency header. Existing SQL limiter composition remains injectable through HttpSecurity; focused tests separately inject deterministic rejection. Real mixed SQL limiter/load evidence is reconciled at P2-PR-020.

Private replies use no-store/noindex/no-referrer and opaque request/error envelopes. Database constraint refusals at this new boundary map to409 rather than exposing an internal integrity error. Missing/wrong-owner resources share404. A private upload uses application/octet-stream with strict query metadata,16MiB maximum and two concurrent binary-body slots per local API instance; default JSON64KiB and existing transport contracts remain unchanged. There is no arbitrary local file or network fetch.

The opt-in0054 extension adds one forced-RLS admission table and fixed functions; default33 app/3 CMS manifests/models and production bootstrap/CLI/preflight/policy/runtime remain unchanged. Before an effect, a separately injected stable key binds verified actor, operation, idempotency key, path/query and canonical payload. Only one concurrent attempt enters; duplicate, changed-body or uncertain attempts return409 and reconcile through a fresh authorized status read. No cached result/permission is replayed, no admitted key automatically expires, no response/private payload is retained, and capacity fails closed at100,000 opaque rows. Actual command-key custody/rotation, retention/cleanup and production capacity approval remain pending; this is not an independent durability/fencing claim. Services retain their own transactional command receipts and expected revisions.
