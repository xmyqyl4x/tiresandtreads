## Pause, rollback and recovery

Pause the affected cohort/channel on ownership/merge leakage, unauthorized or duplicated effects, stale safety/rights decisions, unsupported photo claims, grant/permission bypass, deletion resurrection, signing/update mismatch, unresolved critical/high security issues or breached accepted cost/quality thresholds. Safety/privacy failures take priority over uptime or deprecation promises. Preserve minimized evidence and involve the accepted responders; this packet sends no alert to any person.

Disable new affected work through reviewed server-side admission/kill switches; continue permissible public/manual/P1/P2 journeys. Revoke invalid grants/devices/routes and prevent late workers from publishing. Retain uncertainty/coupon/send/cost identities and current privacy/safety denials. Do not clear ledgers, reset event IDs, retry ambiguous sends as new effects, or restore permission by rolling back code/configuration.

Backend rollback selects an approved compatible image/config and expand-compatible schema. Native rollback stops rollout and, if possible, serves a previously approved update compatible with each installed native runtime. Native library/entitlement changes require a new signed binary; store replacement cannot recall installed/offline copies. Keep old APIs supported while denying revoked/unsafe access, and provide an explicit upgrade/manual/privacy recovery path.

MCP rollback retains approved endpoint/auth/scopes/tool metadata and compatible versions; roll back the server/metadata as a coordinated manifest, rescan/review as required, and disable only affected tools when possible. The current platform can detect server changes independently of ZIP updates; our publication guard must still bind every change to reviewed evidence. Never silently change tool meaning under the same schema version.

Data recovery requires accepted backup/object/key/journal custody and latest-chain restore/deletion replay before admitting clients. A SQL-only archive, parent-held simulated checkpoint or earlier-chain fixture is insufficient. Validate private object/derived artifact erasure, old queued sync events, offline cache reconnection and all current denials before reopening. Preserve actual legal retention decisions; no new retention policy or recovery authority is granted here.

The incident/rollback receipt records candidate/channel/cohort, reason/time, accountable and backup operator, disabled scopes, observed/unknown effects, preserved privacy/cost/safety state, restored versions, actual recovery/compatibility results, approved notifications and owner reopening decision. These fields remain unfilled until the relevant action is separately authorized and observed.
