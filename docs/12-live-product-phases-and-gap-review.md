## Four live product phases

P1–P4 correspond to R1–R4 in traceability. Each phase contains its own S0 → database → repositories/entities → business services → APIs → UI → integrated rollout sequence. Complete **all APIs in that phase** before starting its new product UI. Do not build all four phases' databases before the first website can launch. Reuse accepted foundations, keep the earlier live product supported, and use compatible migrations and feature flags for subsequent releases.

## SEO from the first live release

SEO is a product capability with a content owner and a technical owner. P1 delivers server-rendered public content, stable descriptive URLs, descriptive titles/headings, canonical links, accessible images/alt text, breadcrumb/internal links, typed structured data matching visible facts, XML sitemaps with actual modification dates, environment-aware robots and safe redirects. IndexNow support is for participating engines; it is not a Google indexing promise. Use Search Console verification/submission and a strategic page register at launch; ingest aggregate search metrics daily when credentials and reporting volume permit. No ranking, indexing or rich-result guarantee is made. [Google SEO guidance](https://developers.google.com/search/docs/fundamentals/seo-starter-guide) supports the public-content approach.

| Page class | Index/ad policy | Content and release gate |
| --- | --- | --- |
| Home/assessment | Public canonical landing; assessment state never in indexable URL; no ads | Useful explanatory copy and navigation even before interaction |
| Education, glossary, decoder/checklist guidance | Public indexable content; allowlisted ad slots | Authored/reviewed, attributable sources, review date and correction route; useful with scripts/ads blocked |
| Manufacturer, recall and vehicle/size guidance | Only selected useful pages; expansion P4 | Confirm display rights and currency; editorial approval, original context, evidence and at least three eligible options for recommendation templates; not every imported DB row gets a URL |
| Private reports, shares, compares, account, imports and staff | `noindex`, no sitemap, private caching/access controls; third-party ads absent by default | Robots is not authorization; share URLs/tokens, personal parameters and photo assets never appear in public metadata or structured data |
| Facets, internal search, empty/unsupported combinations | Prevent crawl explosion; noindex or canonical only where content is actually equivalent | Explicit empty states, bounded links, real 404/410 for removed public content, no doorway pages |

P1 CI checks rendered metadata, sitemap membership, redirects, structured data and private-page exclusion. A bounded nightly crawl detects broken links, duplicates, canonical conflicts and missing review dates. Staff reviews findings weekly. Field Core Web Vitals and Search Console reports are marked unavailable when traffic is sparse; lab checks still block regressions. P4 adds suggested internal links, deeper audits and curated programmatic pages. AI outputs are private assistance, never automatically published as indexable pages: editorial review, provenance and user value are required. [Google's AI-content guidance](https://developers.google.com/search/docs/fundamentals/using-gen-ai-content) warns against scaled content without added value.

## Advertising as a core business capability

P1 designs and tests monetizable public education inventory, responsive reserved slots, `ads.txt`, network account/site verification, domain ownership, policy pages, consent, brand/category controls and reconciliation. The initial provider target is AdSense; adapters and slot IDs keep vendor logic out of ranking/UI components. Start with manually placed allowlisted units and Auto ads disabled. Any later automatic placement, anchor or interstitial format requires a fresh placement/performance review.

Retain D02: no home/assessment/form, compare, email/PDF, privacy, account or admin ads; at most two placements after the picks on eligible results surfaces. Private result pages default to house promotions only. Third-party result ads require proof of a provider-permitted, accurately represented, token-free placement whose entire request/DOM/referrer context cannot reveal report data; otherwise leave them disabled. Do not disguise page URLs to evade network rules. Public education is the primary scalable display-ad surface.

All ads are visibly labeled using network-permitted labels, separated from navigation/actions and never disguised as tire advice. Our ≤30% ad-density policy and CLS ≤0.1 are internal constraints, not claims about a Google numeric rule. Reserve responsive space, lazy-load below the fold, cap script work, and test accepted/denied/no-choice consent, ad blockers, slow networks and empty fill. No new ads may delay an assessment or hide warnings. [Google placement guidance](https://support.google.com/adsense/answer/1282097?hl=en) informs labeling and usability.

No nonessential ad requests before the required choice under the existing product policy. GPC/opt-outs and regional vendor-purpose rules are enforced centrally. A Google-certified TCF CMP is required for personalized AdSense ads to EEA/UK/Switzerland users under [Google's publisher requirements](https://support.google.com/adsense/answer/13554116?hl=en); verify the selected CMP and actual traffic locations before activation, including visitors outside the launch market. Certification does not replace our privacy review.

The ad operator owns network approval, ads.txt health, invalid-traffic alerts, blocklists, consent errors, viewability, fill, page/slot RPM, estimated versus finalized revenue, and layout/latency impact. Import aggregate provider reports with period/currency/source and corrections; never join individual ad activity to private report/AI/photo data. Do not click live ads during testing. Use provider-supported test methods and filter internal/bot traffic from product metrics. Report net contribution after content, data, AI and hosting costs. Forecast low/base/high traffic and fill scenarios; neither approval nor income is assumed to fund required service operations.

## Channel and module contracts

Web, Expo and MCP are adapters over the same L3 services/L4 rules. L2 authenticates, validates and applies limits; L5 persists source and AI artifacts in PostgreSQL; L6 wraps NHTSA/licensed feeds, OpenAI, files and jobs. No channel reads DB tables directly or invents its own recommendation rules. Public MCP tools expose licensed public facts only; private tools require explicit scoped authorization and confirmation for sending/deleting. Raw photos and private AI prompts are excluded from public tools and analytics/audience products.

The inbound AI plugin/channel is distinct from outbound AI inference used to enrich reports. The target client integration uses an MCP server and the provider's current packaging/authentication requirements, with optional UI. [OpenAI's current plugin documentation](https://developers.openai.com/plugins) describes MCP-backed plugins; verify supported distribution and SDK versions again at P3. Do not assume that an API key, an MCP endpoint or an older plugin manifest automatically creates a discoverable ChatGPT integration.
